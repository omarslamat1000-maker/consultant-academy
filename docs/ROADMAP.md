# خارطة تطوير مقترحة — أكاديمية المستشار

الحالة الحالية (2026-09-16): التطوير محلي فقط. النشر على Netlify متوقف (فُكّ ربط المجلد بالموقع؛ الموقع القديم يبقى كما هو حتى تحذفه من لوحة Netlify). المستودع على GitHub يُدفع إليه يدويًا فقط عند الطلب.

## التشغيل المحلي الكامل
```bash
npm run dev       # الواجهة  http://localhost:8220
npm run dev:api   # الوظائف  http://localhost:8788 (تعمل عبر القناة الخدمية بلا service_role)
npm run doctor    # فحص المتغيرات
npm test          # 82 اختبارًا
```
مفتاح Gemini يُضاف من لوحة المسؤول → «مفتاح API» (يُحفظ مشفّرًا في Supabase ويُستخدم محليًا وعلى أي استضافة لاحقًا).

## المرحلة أ — جودة التعلم (أولوية عالية، 1–2 أسبوع)
1. **بنك حالات ثابتة أوسع (30+ حالة)** موزعة على 17 قطاعًا و4 مستويات، مع اعتمادها كأمثلة مرجعية للمولّد (Few-shot ديناميكي من الحالات المعتمدة في لوحة المسؤول).
2. **تقييم الحالة التطبيقية بالذكاء الاصطناعي** بدل التغطية النصية الحتمية، بالمخطط نفسه المستخدم في المحاكاة، مع بقاء التصحيح الحتمي كبديل.
3. **توليد أسئلة بنك الأسئلة من الواجهة** (القالب جاهز: `question-generator-prompt`) مع مراجعة المسؤول قبل النشر.
4. **مسار الخبرة الشخصية (PEI)**: محاكاة أسئلة سلوكية بصيغة STAR-R وتقييمها — الوحدة 11 تشرحها لكن لا يوجد تمرين تفاعلي.
5. **تحدي 60/90 ثانية بالصوت**: تسجيل صوتي في المتصفح → تفريغ (Gemini يدعم الصوت) → تقييم التواصل التنفيذي.

## المرحلة ب — التعلم التكيفي المتقدم (2–3 أسابيع)
6. **تقييم الحوار (Interviewer-Led) داخل الدرجة النهائية** بوزن صريح (مثلًا 20% من بُعد التواصل) بدل كونه دليلًا إضافيًا فقط.
7. **مسارات مخصصة حسب الدور** (مدير PMO، محلل أداء، مستشار تحول) تُعيد ترتيب الوحدات وتُثقّل القطاعات.
8. **تكرار متباعد (Spaced Repetition)** للمفاهيم التي أخطأ فيها المتدرب: بطاقات مراجعة قصيرة تظهر في لوحة التقدم.
9. **مقارنة بالأقران** (مجهولة الهوية): موقع المتدرب ضمن توزيع الدرجات لكل مهارة ومستوى.
10. **شهادات إتمام المستوى** (PDF بختم شجرة القضايا) عند تحقق شروط الانتقال.

## المرحلة ج — لوحة المسؤول والجودة (1–2 أسبوع)
11. **مراجعة بشرية منظمة**: طابور حالات/تقييمات عشوائية للمراجعة، وحساب الانحراف الآلي-البشري لكل إصدار Prompt تلقائيًا (البنية موجودة في `ai_metrics`).
12. **A/B لإصدارات Prompt**: توجيه نسبة من الطلبات لإصدار مرشّح ومقارنة نسبة JSON الصالح والتكرار والانحراف.
13. **Golden Cases** كاختبارات آلية: مجموعة حالات وإجابات بدرجات معتمدة تُشغَّل بعد كل تغيير في القالب (`tests/golden/`).
14. **تصدير التقارير** (CSV/Excel) للمستخدمين والمحاولات والإتقان.

## المرحلة د — التقنية والتشغيل
15. **تقسيم حزمة الواجهة** (dynamic import للوحة المسؤول والمحاكاة) لخفض 724KB إلى نحو النصف.
16. **مزود ذكاء ثانٍ** عبر `AIProvider` (مثل OpenAI أو Claude) كاحتياط تلقائي عند فشل Gemini، مع اختيار المزود لكل مهمة (توليد/تقييم).
17. **Supabase Realtime** لتحديث لوحة المسؤول (الحالات بانتظار المراجعة) دون إعادة تحميل.
18. **PWA** (Service Worker + Manifest) للعمل دون اتصال في الوحدات النظرية.
19. **اختبارات E2E آلية** (Playwright) لمسار: دخول → وحدة → حالة → تقييم → سجل.
20. **استضافة بديلة** عند العودة للنشر: Vercel أو Cloudflare Pages بمحوّل صغير للوظائف، أو Netlify بعد تجدد الرصيد؛ الشيفرة لا تحتاج تغييرًا جوهريًا لأن القناة الخدمية لا تعتمد على مزود الاستضافة.
