# دليل إدارة مفاتيح API من داخل التطبيق

## المتطلبات
- حساب بدور `admin` (يُقرأ من `academy.roles`، لا من `user_metadata`).
- `CONFIG_ENCRYPTION_KEY` مضبوط في متغيرات بيئة Netlify (32 بايت base64 أو 64 حرفًا hex). بدونه يكون زر "حفظ آمن" معطّلًا مع رسالة واضحة، ولا يوجد أي بديل غير آمن.

## الشاشة: لوحة المسؤول → مزود الذكاء الاصطناعي
| العنصر | الوصف |
| --- | --- |
| حالة الاتصال | مربوط/غير مربوط، ومصدر المفتاح (التطبيق أو متغير البيئة) والنموذج |
| التشفير الخادمي | جاهز / غير مضبوط |
| API Key | حقل كلمة مرور، لا يُحفظ في المتصفح ولا يظهر بعد الحفظ |
| النموذج / Temperature / الحد الأقصى | إعدادات التوليد |
| اختبار الاتصال | يختبر المفتاح المُدخل (أو المحفوظ إن كان الحقل فارغًا) عبر `/api/ai-provider/test` بحد 5 اختبارات كل 5 دقائق |
| حفظ آمن | `/api/ai-provider/save`: تشفير AES-256-GCM (IV عشوائي + Auth Tag) ثم تخزين؛ يُعطَّل أي مزود نشط سابق |
| قائمة المزودين | اسم المزود، النموذج، آخر 4 أحرف، تاريخ الإضافة ومن أضاف، آخر اختبار ونتيجته، من عدّل |
| تدوير المفتاح | `/api/ai-provider/rotate`: يستبدل السر ويصفّر حالة الاختبار |
| تعطيل / تفعيل | `/api/ai-provider/disable` مع `enable: true/false` |
| حذف | `/api/ai-provider/delete` |

## ضمانات الأمان (مطبّقة في الكود)
1. المفتاح لا يظهر في HTML/JS/Network/Console/Storage/URL: الواجهة تعرض `key_hint` فقط، والاستجابات لا تحتوي `encrypted_secret` (اختبار `tests/integration/functions.test.ts`).
2. لا تخزين نص صريح: `encrypted_secret` + `secret_iv` + `auth_tag`.
3. الجدول `academy.ai_providers` بلا امتيازات لـ `anon`/`authenticated` وبـ RLS بلا سياسات؛ العرض `ai_providers_public` وصفي فقط ومقيّد بـ `is_admin()`.
4. جميع endpoints الإدارية تتحقق من JWT ثم من الدور خادميًا (403 للمتدرب).
5. سجل العمليات `audit_logs` يحذف أي حقل يشبه سرًا (`sanitizeMetadata`) ويخفي الأنماط (`redactSecrets`).
6. حدود المعدل وحجم الطلب (4KB للمسارات الإدارية) ومهلة 20 ثانية لاختبار الاتصال.
7. المفتاح يُرسل إلى Google في ترويسة `x-goog-api-key` لا في URL.
8. `service_role` و`CONFIG_ENCRYPTION_KEY` خادميان فقط ولا يُضمَّنان في حزمة البناء (`tests/security/build-secrets.test.ts`).

## تدوير مفتاح التشفير الرئيس
إذا غيّرت `CONFIG_ENCRYPTION_KEY` فلن يمكن فك المفاتيح المحفوظة سابقًا؛ ستظهر رسالة "تعذر فك تشفير المفتاح المحفوظ" ويجب إعادة إدخال المفتاح عبر "تدوير المفتاح". (لا يُخزَّن المفتاح الرئيس في قاعدة البيانات.)

## إضافة مزود جديد مستقبلًا
أضف تنفيذًا لواجهة `AIProvider` في `server/providers/` وسجّله في `createProvider()`، ووسّع قيود `provider` في الجدول والمخططات. لا تغيير في الواجهة أو منطق الحالات.
